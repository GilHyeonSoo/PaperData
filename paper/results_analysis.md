# 시뮬레이션 결과 분석

## 0. 1시간 wall-clock 공식 실행 결과
본 절은 공식 wall-clock 실행 데이터를 기준으로 작성하였다. 참고용 단일 조건 실행 결과는 민감도 확인용으로만 사용하고, 논문 본문에서 S1-S5 장시간 시나리오를 설명할 때는 본 절의 결과를 우선 사용한다.

### 0.1 실행 검증
- 기준 데이터: S1-S5 공식 wall-clock 실행 결과
- 통합 요약: 시나리오별 실행 규모와 성능 지표
- 전체 run 요약: 개별 run 단위 성능 지표
- 논문용 시나리오 집계: S1-S5별 요약 지표
- 논문용 모델 집계: 기능 조합 조건별 정규화 지표
- 전체 run 수: 196개
- 비교 모델: A, B, C, D
- 시나리오별 실제 실행 시간: 약 60.1-65.2분
- 패드 점유 겹침 검증 결과: 196개 패드 사용 로그 파일 전체에서 0건

## 1. 참고용 단일 실행 개요
- 실행 구분: 참고용 단일 조건 실행
- 실행 실험 수: 64개
- 결과 요약 행 수: 64행
- 원시 궤적 로그 행 수: 204,077행
- 패드 사용 로그 행 수: 6,320행
- 기본 안전거리: 500 ft, 약 152.4 m
- 민감도 안전거리: 30 m
- 속도 시나리오: 150/240/300 km/h를 내부에서 41.667/66.667/83.333 m/s로 변환
- 버티포트 시나리오: 4/8/20개
- 버티포트 패드 점유: 활성화, 버티포트당 패드 1개
- 이륙 패드 점유시간: 30 s
- 착륙 패드 점유시간: 190 s
- 연구 범위: 도시 격자 맵, 건물 회피, 비행체 간 충돌 회피, 버티포트 패드 점유 모델 중심

## 2. 패드 점유 로직
새로 추가된 패드 점유 로직은 같은 버티포트에서 두 eVTOL이 동시에 이륙 또는 착륙하지 못하도록 한다.

- 이륙 시 출발 버티포트 패드가 점유 중이면 실제 이륙 시작시간을 다음 사용 가능 시점까지 지연한다.
- 착륙 시 목적지 버티포트 패드가 점유 중이면 eVTOL은 목적지 상공 순항고도에서 `landing_wait` 상태로 대기한 뒤 하강한다.
- 패드 점유 구간은 별도 로그로 기록된다.
- 패드 대기시간은 이륙 대기, 착륙 대기, 총 패드 대기 지표로 기록된다.
- 전체 결과 검증에서 같은 시나리오·버티포트 내 패드 점유 구간 겹침은 0건으로 확인되었다.

## 8. 결과 해석 시 주의점
- 본 결과는 단순화된 격자 도시와 지도 기반 충돌 탐지 모델의 결과이며, 실제 eVTOL 운항 안전성을 직접 보장하지 않는다.
- 패드 점유 로직은 버티포트당 패드 1개, 이륙 점유 30 s, 착륙 점유 190 s라는 단순 모델이다.
- 착륙 대기 중 eVTOL은 목적지 상공의 순항고도에서 대기하는 것으로 처리되며, 이 대기 구간도 비행체 간 충돌 탐지에 포함된다.
- 건물 높이, 격자 크기, 도로 폭, 수직속도, 수직 통제고도 등 일부 값은 문헌 직접 근거가 아니라 시뮬레이션 가정값이다.
